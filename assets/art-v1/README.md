## 图集索引与动画

以 [manifest.json](manifest.json) 为权威索引，包含尺寸、SHA-256、透明通道、素材矩形、动画顺序及锚点。

**行列只表示阅读顺序，不能按等分网格裁切。** 图像生成造成的间距偏差已通过轮廓分析修正坐标。机器人和植物采用实际轮廓矩形；大树与陈设采用显式矩形，避免截断脚尖、工具或树冠。原始PNG像素未作程序抠图或重绘。

机器人从上到下：idle、walk、tend、water、rest、communicate；每行从左到右0—3帧。

| 动作 | 建议播放速度 | 触发 |
| --- | --- | --- |
| idle | 3fps，循环 | 空闲、眨眼、呼吸 |
| walk | 6fps，循环 | 移动；左右可镜像角色层 |
| tend | 4fps，单次 | 照料、播种、收获 |
| water | 4fps，单次 | 浇水；水滴另外叠加 |
| rest | 2fps，循环 | 休息、树下新生活行为 |
| communicate | 4fps，单次 | 接听、注意玩家 |

机器人／植物的anchors是原图绝对像素坐标。设source rect为[sx,sy,sw,sh]、anchor为[ax,ay]，目标落点为[px,py]、比例为k，则绘制位置为[px+(sx-ax)×k, py+(sy-ay)×k]，绘制大小为[sw×k, sh×k]。不要逐帧分别缩放到相同外接框，否则水壶动作会让机身忽大忽小。

## 检查结果与边界

- 10张选用母版均已保存到本项目，尺寸与哈希有索引。
- 两张不透明图片为远景和干旱插图；其余八张含有效透明通道。
- 实际识别到24个完整机器人轮廓及9个植物轮廓；索引矩形均位于图片范围内。
- 本地Chromium已实际加载全部10张图并截取方屏组合，检查了透明窗、角色、三种植物、树冠和按钮区。
- 原图是高分辨率母版，尚未导出成ESP32用的最终尺寸与编码。图集动作仍需实机检查节奏、手脚连贯性与边缘，不能把母版预览当作设备性能验收。
- 远近景循环边缘未认定为严格无缝，接入时检查并按需加入循环过渡。
- 当前未修改固件、云端角色或任何游戏存档；没有加入动物、水池、多建筑或滑动车厢。

下一阶段按实际场景大小导出素材，接入现有LVGL对象与游戏状态，复测帧率、语音并行和已验收触摸手感。
